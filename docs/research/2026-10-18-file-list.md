## The loader

`virtual74` runs one step per frame on `_proc`, unless `beSystem::_execDvdErr` is set.

| Step | What it does |
| --- | --- |
| 0 | Sets the stage name from the first queued `beFileListInfo` and loads `loadingUSA/ld<first two letters of the stage>.igb`. |
| 1 | Gives its infos to the insight core. The first time, adds `BecText.igb` and `_common/sbiallse.igb`. Moves the list's sound files first: a name whose part after the first `/` starts with `s`. |
| 100, 101 | Loads them; asks the sound manager (`SOUND`: `SEARCH`, `MAKEBINLIST`, `ISDONETRANS`). |
| 102, 2 | Loads the list's other files. |
| 3 | Runs the stage's `func.lua` and `boot.lua` (`<stage>/lua`). |
| 4 | Loads the system's resident files (`beSystem::_readFileList`), waits for the loading screen (`beLoadingNode`) and reads the important infos. |
| 20, 21 | Two frames. |
| 5 | Gives the read infos to the insight core. |
| 6 | Shows the loading layer (`LAYERCTL`) and gives each scene graph its layer node. |
| 7 | Initialises the text control and runs `start.lua`. |
| 8 | Sets `beSystem::_isActive`. |
| 9 | Runs `first.lua`. Re-allows soft reset except on `stagIS08`/`09`/`10`/`12`. |

**Loading a list** (`fn_802F9E98`). Alchemy's `igResource` (the global at `lbl_80562104`) loads one file at a time. `beCri.h` previously called it "the memory manager". When the file's directory is loaded, its infos are sorted:
- Lua infos go to the insight core;
- scene infos with cameras, or with a scene graph named `ROOTATTR`, go to the important list;
- other scene infos go to the queue;
- the rest go to the read list.

**Pools.** Before the first files, `_onetimeCount` points the resource manager's object and data pools at the resident pools (2) or this manager's pools (0).

**Original behaviour reproduced:**
- The read-list insertion looks for the first scene info but tests the new info's own class each time, so it always appends.
- The `notDefined` stage-name fallback can never be reached.

## Open

- **A loop with an early `break`** (the `/` search in step 1): the original keeps an index and re-reads `_length` each pass, while this source becomes a `ctr` loop. `beSound`'s effect loop is the same pattern. Ruled out:
  - every compiler from 1.3 to 2.7;
  - index types;
  - the loop written with `while`;
  - auto-inlining of the text accessor;
  - the optimizer pragmas.
- **Reloads after a loop** (`fn_802FA53C`, and `virtual74`'s scene child list): the original reloads a value that MWCC here keeps from the loop condition. `#pragma opt_common_subs off` does not reproduce it.
- **Register colouring:** `fn_802F9E98` and `virtual70`.
- **`.rodata`:** the strings (`0x80425590..0x804256C0`) are in this source's order of first use. One unit could own them once `virtual74` and `fn_802F9E98` match.
